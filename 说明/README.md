## 本轮验证结论（先看这个）

需求是「验证前端能否通过后端对数据库**所有表项**做增删改查，**查询条件包含所有字段单独或联合查询**」。
结论：**能**。分四层拿到的证据：

| 层 | 做法 | 结果 |
| --- | --- | --- |
| 后端接口 | `tools/_verify_all_tables.mjs` 跑在 8899 隔离副本库上，真实 HTTP | **8399 条断言，0 失败 0 跳过** |
| 前端界面 | `tools/_verify_crud_ui.mjs` 真浏览器 + 真点击（**不直接调 API**），逐列驱动筛选控件 | 全量跑完即 62 张表，逐列扫描无跳过 |
| 多态表复验 | 单独重跑 `person_form` / `person_disc` | **25 条断言，0 失败 0 跳过** |
| 打包产物 | 真启动 exe，读内嵌 API，清空 6 张表后重启看是否回填 | 窗口正常打开；**6 张表被原样自动回填**（证明内嵌前端→随机端口后端链路通） |

过程中修掉的问题见 **07 篇第 10 节**（3 个真 bug + 1 个功能缺口 + 1 个验证脚手架缺口）。

## 一分钟上手（已拿到 exe 的人）

1. 把 `Application/` 整个目录拷到目标机器即可（单文件版只要 `bcrm-desktop.exe`；用便携版则连 `EXE/` 一起拷）。
2. 双击 `bcrm-desktop.exe`（或先跑安装包 `BCRM客户管理系统_1.0.0_x64-setup.exe`）。
3. 首次启动会看到窗口标题「BCRM 客户管理系统」，`crm.db` 在同目录生成。
4. 若系统缺少 **WebView2 运行时**（仅 Windows 10 早期版本可能缺），程序会打不开窗口 —— 装一次 [WebView2 Runtime](https://developer.microsoft.com/microsoft-edge/webview2/) 即可；本项目的 NSIS 安装包采用**在线引导器**，安装时会自动联网下载并安装 WebView2（需联网）。
5. 若「双击打不开、但重新运行安装程序时自动打开能开」：这是**曾以管理员身份运行过**、导致 WebView2 数据目录被管理员占用所致 —— 双击 `Application/修复启动.bat` 即可复原（详见 01 篇第 5 节）。
6. ⚠️ 若**双击毫无反应、且程序目录里连 `bcrm-launcher.log` 都没生成**，这**不是程序的问题** —— 是公司电脑上的终端管控软件（奇安信天擎等）在**进程创建阶段**把程序拦掉了。请看 **[10 篇](./10-终端管控拦截：机制与解决方案.md)**（内含可直接交给 IT 的加白申请单）。**注意：右键「以管理员身份运行」不能绕过，签名也不能。**

> 数据库位置规则：**优先 exe 同级 `crm.db`**；若该目录不可写（例如装在 `C:\Program Files` 且普通用户双击运行），自动回退到 `%LOCALAPPDATA%\Bcrm\crm.db`，并在 `bcrm-launcher.log` 里写明实际路径。
> ⚠️ 请始终**直接双击 / 走快捷方式**启动，**不要右键「以管理员身份运行」**，否则会再次触发上一条问题。

## 一分钟上手（从源码构建的人）

```bash
# 0. 前置：Rust(MSVC) + Node 18+ + VS2022 生成工具（详见 01 篇）

# 1. 先构建前端产物 —— 顺序不能反！
cd frontend && npm install && npm run build

# 2. 再编桌面壳（把前端产物与后端库编进一个 exe）
cd ../launcher && cargo build --release     # 首次约 5–15 分钟（~500 crate + LTO）

# 3. 组装交付目录
mkdir -p ../Application
cp target/release/bcrm-desktop.exe ../Application/bcrm-desktop.exe
#    不必预置 crm.db —— 首次运行会自动建库

# 4.（可选）打 NSIS 安装包（含 WebView2 离线捆绑）。需先装 Tauri CLI：
#    cargo install tauri-cli --version "^2"
cd ../launcher && cargo tauri build      # 产物：target/release/bundle/nsis/*.exe
```

**顺序颠倒会静默出错**：`launcher/build.rs` 的 `cargo:rerun-if-changed=../frontend/dist` 只能
**触发重编**，不会替你先把前端构建出来。跳过第 1 步的后果是 exe 里嵌的还是上一版界面 —— 最难排查的一类问题。

开发态更省事的做法是前后端分开跑（见 01 篇第 3 节）—— 或者直接用根目录的一键脚本：**双击 `启动Web服务.bat`**。

| 场景 | 命令 | 它做什么 |
| --- | --- | --- |
| 开发 / 联调 | `启动Web服务.bat` | 编后端 → 起后端（默认 8787）→ `npm install`（缺依赖才装）→ `npm run dev`（5273，改前端即时生效）→ 自动开浏览器 |
| 交付 / 演示 | `启动Web服务.bat -Mode release` | 编后端 → 起后端 → `npm run build` → `npm run preview`（起静态产物）→ 自动开浏览器 |
| 只起一半 | `启动Web服务.bat -Service backend`（或 `frontend`） | 单独起后端 API / 单独起前端页面 |
| 换端口 | `-Port 9000` / `-WebPort 6000` | 8787 被占用时会自动往后找空闲端口 |
| 停止 | `启动Web服务.bat -Stop` | 结束本项目端口上的服务（只结束本项目的进程） |
| 换 npm 源 | `-Registry https://registry.npmmirror.com` | 内网 / 下载慢时用 |

配套细节：后端端口变化时，前端通过 vite 的 `/api` 反代自动跟随，**不用改代码、也不用重新构建产物**；`-Reinstall` 可强制走 `npm ci` 重装依赖；`-NoBuild` 直接用已有产物。

> ⚠️ 后端只监听 `127.0.0.1`，且**当前 API 没有任何鉴权** —— 这套脚本请**不要**改成对外（`0.0.0.0`）暴露。
> ⚠️ 它也**不能绕过终端管控**：`cargo` 新编出来的 `bcrm-backend.exe` 同样是云端没见过的哈希，照样会被拦（见 10 篇）。浏览器版的意义是「**换一种交付形态**」的雏形，不是绕过手段。

> **编完必须真启动一次**：`cargo build` 成功只证明能编译，证明不了能跑。
> 判据是 exe 同级 `bcrm-launcher.log` 的**末行是不是「窗口已创建」** —— 01 篇 4.5 / 4.6 两个坑
> 都是编译 0 错误、但程序在建窗口前就 panic 退出。
