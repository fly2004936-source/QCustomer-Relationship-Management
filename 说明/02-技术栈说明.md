# 02 · 技术栈说明

> 本文回答三个问题：**用了什么**、**什么版本**、**为什么是它**。
>
> 版本号全部取自项目实际锁文件（`Cargo.lock` / `package-lock.json`）。

---

## 一、总览

```text
┌──────────────────────────────────────────────────────────────┐
│  bcrm-desktop.exe  （单文件，约 11 MB）                        │
│                                                              │
│  ┌────────────────────────┐   ┌──────────────────────────┐  │
│  │  Tauri v2 WebView 壳    │   │  内嵌 axum 后端服务       │  │
│  │  · 加载编入的 Vue 产物   │←→ │  · 127.0.0.1:随机端口     │  │
│  │  · 注入 API 基地址       │HTTP│  · 通用 CRUD 引擎         │  │
│  └────────────────────────┘   └───────────┬──────────────┘  │
│                                            │ rusqlite        │
│                                  ┌─────────▼──────────────┐  │
│                                  │  同级 crm.db (SQLite)   │  │
│                                  └────────────────────────┘  │
└──────────────────────────────────────────────────────────────┘
```

**一句话**：一个 exe = 一个 WebView 界面 + 一个进程内的 HTTP 服务 + 一个 SQLite 文件。没有任何外部依赖需要安装。

## 二、后端技术栈（`backend/`）

| 依赖 | 版本 | 用途 | 为什么选它 |
| --- | --- | --- | --- |
| **Rust** | 1.98.1（edition 2021） | 语言 | 单文件静态编译、无运行时、内存安全；和 Tauri 同生态 |
| **axum** | 0.8.9 | HTTP 框架 | 与 `tokio` / `tower` 生态贴合最紧；`Router` 的 `with_state` 让「一套处理器服务 62 张表」写起来很干净 |
| **tokio** | 1.53.1 | 异步运行时 | axum 的底座。启用 `rt-multi-thread` / `macros` / `net` / `signal` |
| **rusqlite** | 0.40.2（`bundled`） | SQLite 驱动 | **`bundled` 特性把 SQLite C 源码一起编进来**，交付时不需要目标机器装 SQLite DLL —— 这是做便携 exe 的前提 |
| **serde** / **serde_json** | 1.0.229 / 1.0.151 | 序列化 | 请求/响应体、元数据白名单、JSON 列读写全靠它 |
| **tower-http** | 0.6（`cors`） | CORS 中间件 | 打包后界面在 `tauri://localhost`、接口在 `http://127.0.0.1:<port>`，**跨源是常态**，CORS 层是必需品而非开发期补丁 |
| **form_urlencoded** | 1.2.2 | 查询串解析 | 把 `filter[列名__操作符]=值` 这类嵌套键解析出来 |

### 关键设计取向

- **零 ORM**。全部 SQL 由 `query/` 模块按元数据拼装，没有 derive 宏、没有迁移框架。原因是这张库有 62 张表、838 列，用 ORM 会产生上千个结构体，而通用 CRUD 只需要「列名 → 值」的泛化模型。
- **单连接 + `Mutex`**。桌面单用户场景并发极低，单连接规避了 SQLite 写锁竞争，代价可忽略。
- **`panic = "abort"`**（release）。减小体积；桌面程序崩了就重启，不需要 catch-unwind。

## 三、前端技术栈（`frontend/`）

| 依赖 | 版本 | 用途 | 为什么选它 |
| --- | --- | --- | --- |
| **Vue 3** | `^3.5.13` | 框架 | 组合式 API + `<script setup>` 足够表达这套界面；单文件组件让模板/逻辑/样式集中 |
| **Vite** | `^5.4.11` | 构建 | 冷启动毫秒级，生产构建把产物压到约 254 KB JS + 100 KB CSS（gzip 后 95 KB + 19 KB） |
| **@vitejs/plugin-vue** | `^5.2.1` | SFC 编译 | — |

**没有引入的东西**（同样是设计决策）：

| 没用的 | 替代方案 | 原因 |
| --- | --- | --- |
| Vue Router | `App.vue` 里一个 `view` ref + `v-if` 分支 | 只有 6 个视图，且桌面程序没有 URL 语义需求；省掉一个依赖和一层心智负担 |
| Pinia / Vuex | `composables/` 下的 `useDataSource` / `useTheme` / `useToast` | 全局状态只有「数据源」「主题」「提示」三块，`ref` + 模块级单例足够 |
| Element Plus 等 UI 库 | 自己写的 `components/` + 2697 行 `app.css` | 项目核心卖点之一是 **11 套可切换视觉风格**；UI 库会带来难以覆盖的默认样式，反而拖累换肤 |
| 图表库（ECharts 等） | 手写 SVG（`OrgGraph.vue` / `GraphView.vue` + 驾驶舱的 `components/cockpit/*`） | 需要「拖拽节点、连线高亮、项目作战侧栏」这类定制交互，通用图表库改造成本高于自绘；驾驶舱的环形/条形/柱状/散点/雷达也都按这套约定手绘 |
| Tailwind | 手写 CSS + 设计令牌 | 11 套主题靠一组 CSS 变量驱动，Tailwind 的原子类在换肤场景下不占优势 |

## 四、桌面壳技术栈（`launcher/`）

| 依赖 | 版本 | 用途 |
| --- | --- | --- |
| **tauri** | 2.x | 提供窗口、WebView、资源打包、`generate_context!` 编译期嵌入前端 |
| **tauri-build** | 2.x | 构建脚本：把 `tauri.conf.json` 的图标/清单/权限编进 exe 资源段 |
| **bcrm-backend** | `path = "../backend"` | **直接把后端当库依赖**，不是另起一个 sidecar 进程 |
| axum / tokio / serde_json | 同后端 | 在 Tauri 的异步运行时上挂 axum |

### 为什么把后端编进同一个进程，而不是 sidecar

| 方案 | 交付物 | 问题 |
| --- | --- | --- |
| sidecar（两个 exe） | `app.exe` + `bcrm-backend.exe` | 要处理「先起后端再起界面」的时序、端口协商、退出时残留进程 |
| **同进程内嵌（本项目）** | **一个 exe** | 关窗口 = 进程整体退出，无残留；端口用 `bind(127.0.0.1:0)` 由系统分配，无协商成本 |

代价是改后端要重编整个 launcher（Rust 增量编译约几十秒），可接受。

## 五、数据层

| 项 | 值 |
| --- | --- |
| 引擎 | SQLite（通过 `rusqlite` 的 `bundled` 静态编译） |
| 表数 | **62** 张 |
| 列数 | **848** 列（含主键） |
| 索引 | **32** 个 |
| 外键 | **55** 条（**40 张表带外键**，22 张无外键约束） |
| 唯一键组 | **10** 组（含 `customer.crm_code`、`project_c74111.project_id` 等） |
| 日志模式 | **WAL**（`journal_mode=WAL`）+ `busy_timeout=5000` |
| 外键开关 | 每个连接 `PRAGMA foreign_keys=ON` |
| 类型约定 | 金额 `REAL`（**单位：万元**）；时间 `TEXT` ISO8601；布尔 `INTEGER` 0/1；枚举 `TEXT + CHECK`；多值 `TEXT` 存 JSON（走 SQLite JSON1 函数） |

## 七、选型对照速记

| 需求 | 选择 | 一句话理由 |
| --- | --- | --- |
| 62 张表的 CRUD 不想写 62 套代码 | 元数据驱动的通用引擎 | 表结构是数据，不是代码 |
| 交付要「一个文件、双击即用」 | Tauri + rusqlite(bundled) + 内嵌后端 | 无外部运行时依赖 |
| 要能随便换视觉风格 | CSS 变量 + 自绘组件 | UI 库样式无法完全接管 |
| 复杂查询（全字段任意组合） | 自研查询 DSL → SQL 编译 | 需要 `filter[a__op]=v` 这种对前端友好的语法 |
| 桌面单用户 | SQLite 单连接 + 互斥锁 | 并发压力可忽略 |
