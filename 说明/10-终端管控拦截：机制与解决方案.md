# 10 · 终端管控拦截：机制与解决方案

> 适用对象：运维 / IT / 项目负责人
> 结论依据：2026-09-14 ~ 2026-09-16 在本机（奇安信天擎 10.8.0.8000 管控环境）的**日志取证与实测**，全部证据可复核，复核方法见 §8。
> 本文**修正**了 `09-更新说明.md` §四 与此前口头结论中的三处错误，见 §4。

---

## 0. 一句话结论

双击 `bcrm-desktop.exe` 不是"打不开"，而是**进程根本没有被创建**：公司统一部署的奇安信天擎，在内核层截获"进程创建"回调，用一条**云端规则** `CloudRule.Block.Strangesoftware`（陌生软件）**静默拒绝**（不弹窗、不提示）。

**它与签名无关，与路径无关，与文件名无关，与是否管理员身份运行无关。** 唯一有效的解法是让程序**被管控系统认识**（加白/加信任），或者**让客户端不再需要创建这个进程**（改为浏览器访问）。

## 2. 拦截是怎么发生的（证据链）

### 2.1 链路

```text
双击（或任何方式启动）
  ↓
Explorer 调用 CreateProcess
  ↓
奇安信内核驱动 QaxComInj64.sys 截获“进程创建”回调
  ↓
天擎 HIPS 引擎  module.HipsEngShim  →  请求“云端规则”判定
  ↓
云端返回 CloudRule.Block.Strangesoftware（陌生软件）
  ↓
★ 进程不创建、不弹窗、不留我们程序自己的任何日志
```

| --- | --- |
| 产品 | 奇安信天擎 10.8.0.8000（模块版本 10.8.0.7000） |
| 安装目录 | `C:\Program Files (x86)\Qianxin\Tianqing` |
| 内核驱动 | `C:\windows\system32\drivers\QaxComInj64.sys`（Running） |

字段含义：

| 字段 | 值 | 含义 |
| --- | --- | --- |
| `szVirusName` | `CloudRule.Block.Strangesoftware` | **云端规则**：陌生软件 → 阻止 |
| `nType` | `进程(1)` / 风险侧为 `危险进程(4)` | 拦截点是**进程**（不是文件读写、不是网络） |
| `nHandleType` | `建议阻止(2)` | 动作 = 阻止 |
| `nLevel` | `40` | 威胁级别 |
| `szMD5` / `szSHA1` | 被拦文件的哈希 | **判定对象 = 文件（内容）** |
| `Process::szProcess` | 目标 exe 全路径 | 即将被创建、但被拒绝的进程 |
| `Process::nPPid` | `3540` / `9832` / `18312` / `20880` | 父进程 = **Explorer**（= 用户双击） |
| `handle.nActionResult` | `没有这个项(0)` | **没有任何弹窗/交互** —— 静默拒绝 |

> 这解释了一个典型现象：**双击毫无反应，程序目录里连它自己的日志都没生成**。程序的第一条语句都没执行到 —— 这是"被创建前拦掉"的标志性特征，也是区分「程序自身 bug」与「终端管控拦截」的最快判据。

## 4. 三个被证伪的猜测（不要再做无用功）

### 4.1 ❌「因为程序没签名」

**反证零 —— 活体对照（2026-09-16 复核，最直接的一个）**：

桌面上那个 **`PdfToImgs v2.0.exe`** 也是**无签名**的，今天 **00:47 双击正常启动、窗口都弹出来了**（日志原文见下），而同一分钟内 bcrm 正被这条规则拦在外面。

| 观察项 | `PdfToImgs v2.0.exe`（**能跑**） | `bcrm-desktop.exe`（**被拦**） |
| --- | --- | --- |
| 数字签名 | **无**（`sign:` 为空、`company:` 为空） | 无（`sign:` 为空） |
| 软件管控分类 | `Process classify, type=1024` | `Process classify, type=1024` |
| 进程管控判定 | `White process exception!` → `PROCESS_RETURN_NONE` | `White process exception!` → `PROCESS_RETURN_NONE` |
| **HIPS 云规则记录** | **0 条**（从未被送去云端判定） | **144 条** `CloudRule.Block.Strangesoftware` |

```text
# PdfToImgs 今天的启动记录（module.PopupBlockPlugin / QCMFileAudit）
00:47:22.947  文件[c:\users\jingyifei\desktop\pdftoimgs v2.0.exe] 的签名信息错误   ← 无签名，仅记录
00:47:23.156  ProcessMonitorCallback: Create ... PdfToImgs v2.0.exe:20096      ← 进程创建成功
00:47:24.521  OnPupUp! 窗口标题=Pdf转图片工具 v2.0 by CarsonYang ...            ← 窗口已弹出
```

⇒ **本地每一道关卡对这两个文件的结论完全一模一样**，唯一的差别是：bcrm 被送去做云端判定、PdfToImgs **根本没被送**。
⇒ 签名是不是判据，这里给出了第三个、也是最干净的一个反证。

**反证一**：带 Rust 官方 Authenticode 数字签名的 `rustup-init.exe`，**照样被同一条规则拦**（§3）。
**反证二**：本机编译工具链（`cargo`、`rustc`、`rc.exe`、`build-script-build.exe` 等大量未签名 exe）**全部正常放行**。`QCMProcMgr` 全量 31,366 次判定 = 30,083 次 `PROCESS_RETURN_NONE` + 1,283 次 `PROCESS_RETURN_PASS`，**`PROCESS_RETURN_BLOCK` 一次都没有** —— 说明"未签名"本身不是拦截条件。
**反证三**：判定字段里虽然有 `sign:` 字段（本程序为空），但同一条规则连**有签名**的 rustup 也拦 ⇒ 签名不是判据。

> 结论：**签名不能解决"被拦"**。签名真正有价值的地方见 §5-C。

**那到底按什么判？** 上面这张表把范围收得很窄：判定发生在**云端**（本地四道关卡全部放行），而云端能拿到的输入只有**文件本身**（哈希/大小/PE 特征/签名）+ 进程上下文。结合"每次重新编译产生的新哈希**立刻**被拦"这一现象，最合理的解释是：

> **云端认识这个文件 → 放行；云端没见过 → 判"陌生软件"。**
> `PdfToImgs` 是 2021 年起就公开流传的小工具，云端软件信誉库**早就有它**；`bcrm` 是我们自己编译的，**每个版本都是全网唯一的哈希**，云端永远"没见过"。

**想自己验证一遍？** 把 PdfToImgs 复制一份、**只改 1 个字节**（破坏它的哈希），再双击试试：

```powershell
$src = "C:\Users\JINGYIFEI\Desktop\PdfToImgs v2.0.exe"
$dst = "C:\Users\JINGYIFEI\Desktop\PdfToImgs_改了1字节.exe"
Copy-Item -LiteralPath $src -Destination $dst -Force
$fs = [System.IO.File]::Open($dst, 'Append'); $fs.WriteByte(0); $fs.Close()
"新 MD5 = " + (Get-FileHash -LiteralPath $dst -Algorithm MD5).Hash
```

**若副本被拦、原件照跑** ⇒ 判据确实是「云端按哈希认不认识这个文件」，与签名、目录、文件名都无关（这也正好解释了为什么改路径/改名都没用）。
测完删掉副本：`[System.IO.File]::Delete($dst)`。

> ⚠️ 这条推论目前**只在本地侧取证**（云端不给看）。本地能确证的只有：`bcrm` 被上报 144 次、`PdfToImgs` 被上报 0 次、两者其余检查完全相同。上面的"云端认不认识"是**解释**，不是日志直接写明的字段。

| --- | --- |
| `244ccfcd…` | `Desktop\bcrm-desktop\bcrm-desktop.exe` 与 `Desktop\源码\demo\BCRM客户管理系统.exe`（**目录 + 文件名都不同**） |
| `40ba5509…` | `Desktop\源码\Application\bcrm-desktop.exe` 与 `Desktop\Bcrm3.0\bcrm-desktop.exe` |
| `5adf3462…` | `源码\launcher\target\release\bcrm-desktop.exe` 与 `源码\Application\bcrm-desktop.exe` |

> 判定对象是**文件内容哈希**，与路径、文件名无关。
>
> 补充（2026-09-16 复核）：`da140ab5…` 这个哈希在 `%TEMP%\bcrm_v2final\` 下**确实有过一次放行**（09-16 00:08:24，日志 `White process exception!`，进程起来了还拉起了 WebView2），但同一哈希在 Desktop 下的两个路径都被拦。原因是云端判定**异步**：第一次遇到先放行并上报，结论回传后才按结论执行。所以"偶尔能跑起来一次"**不代表它过了**，不可依赖（详见 `09-更新说明.md` §四）。


### 4.3 ❌「右键以管理员身份运行可以绕过」—— 本结论撤回

`09-更新说明.md` 早期版本写过"实测可绕过"，**这个结论不成立，现予撤回**：

1. 144 条记录里**没有任何一条**能证明提权后被放行；拦截发生在内核的进程创建回调，创建者是否提权并不改变被创建文件的哈希。
2. 同一 MD5 在数小时内被**反复**拦截（`0b73cb1d…` 12 次、`13c448e0…` 6 次、`4b235ed1…` 8 次），与"提权可绕过"直接矛盾。
3. 唯一一次"放行"另有原因，见 4.4。

## 5. 解决方案

### A. 客户端「信任区」自助加白 —— 先试这个

**路径**：天擎客户端主界面 / 托盘图标 → **设置中心 → 信任区**（对应程序 `AVTrustZone.exe`）。

官方口径（管理员手册 §3.3.1.4 信任区设置）：支持三种信任数据 —— **文件全路径 / 文件路径 / 扩展名**，其中

> **文件路径**：位于该路径下面的文件及其子路径全部被跳过；适用于**安装路径固定、文件特别多的软件加白**。

官方口径（§3.3.1.6 终端用户安全操作控制）列出的可控项包括"禁止终端用户管理**路径/文件白名单**""禁止终端用户管理**扩展白名单**"——反过来说明**默认情况下终端用户可以自行管理这些白名单**。

- ✅ **首选加「文件路径」（目录）**：一次覆盖该目录下所有文件与子目录，以后换版本不用重新报备。
- 若按钮灰掉 / 要求管理员密码 ⇒ 说明被控制台托管了，走 B。
- 加完后**建议重新触发一次**（重新双击）再判断，必要时按官方建议对信任区做一次扫描。

### B. 让 IT 在控制台加白 —— 最正规、最可落地

天擎控制中心 → **策略中心**（分组策略 / 基线策略，基线优先级最高）→ 病毒防护 / 管控策略：

1. **信任区 → 文件路径（目录）** ← **推荐**
   - 把交付目录（例如 `D:\BCRM\`）整体加白，覆盖该目录及其子目录全部文件。
2. 备选：**管控策略 → 进程白名单**（运维管控类）。
3. ⚠️ **不建议只加"文件全路径"或"文件白名单（MD5）"**：本项目**每次重新编译 MD5 都会变**，意味着每次出新版本都要重新报备一次，迟早会漏。
   - 如果确实要按 MD5 加白：单文件 < 100 MB 用 **MD5**；> 100 MB 才需要 PMD5（本项目两个 exe 分别 11.0 MB / 4.7 MB，**只需要 MD5**）。
4. ⚠️ 与"程序自身写文件"类的问题不同，**这里的加白是"允许创建进程"**，改的是 HIPS/应用管控，不是病毒查杀排除项。

### C. 给程序签名 —— 不是为了"通过校验"，而是为了拿到一个**稳定加白锚点**

修正上一版文档的说法：**签名本身不能让它不被拦**（§4.1 已证）；但签名能让 IT 的加白**一次覆盖所有未来版本**。

官方口径（管理员手册 §3.3.1.5 文件数字签名设置）：

> 将文件的数字签名名称拉黑或者加白。**推荐使用该功能加白无安全隐患的自研软件。**

- 用的证书：**企业内部 CA（AD CS）签发的代码签名证书即可**，不需要买商用 OV/EV —— 天擎比对的是**签名者名称**这个字符串，不要求公网信任链。
- 收益：签名者名称 **不随版本变化** ⇒ IT **加白一次，之后所有版本自动放行**，不用再反复给 MD5。
- 代价 / 注意：
  - 要走一遍企业证书申请流程；
  - **签名会改变文件哈希** ⇒ 如果 IT 已经按 MD5 加白了，签名会让那份白名单**立即失效**。**"签名 + 按签名者加白" 与 "未签名 + 按 MD5 加白" 只能选一条。**
  - NSIS 安装包内嵌的 `bcrm-desktop.exe` 是**独立文件**，签安装包**不覆盖**它。

### D. 改交付形态：不落地 exe（程序侧唯一能"彻底"规避的路）

本系统本质是「HTTP API + 浏览器前端」，完全可以不要桌面壳：

- 把 `backend` 部署到一台内网服务器 / 固定机器，绑 `0.0.0.0`，用户**用浏览器访问**即可。客户端**没有任何进程被创建**，管控无从拦起；也顺便解决了"每个人都要装一份"的问题。

现状与**必须的改动点**（已核对源码）：

| 项 | 现状 | 说明 |
| --- | --- | --- |
| 监听地址 | `backend/src/main.rs:74` 写死 `format!("127.0.0.1:{port}")` | 需增加 `--host` 参数才能对外服务 |
| 前端 | `frontend/dist/` 已是纯静态产物 | 随 backend 一起托管即可 |
| ⚠️ **鉴权** | **当前 API 没有任何认证** | `api/v1` 暴露全部 62 张表的增删改查。**直接暴露到局域网 = 客户数据裸奔**，必须先加认证（+ 建议网段白名单），这一步是**前置条件**，不是可选项 |
| 并发 | SQLite（WAL） | 多人并发写需要考虑（当前是单机桌面假设） |

适合：多人使用、或想彻底摆脱终端策略的场景。

### E. 走天擎「软件分发」通道下发

控制台「软件分发」下发的程序会被登记进软件资产，通常不再被判为陌生软件。适合有服务器托管安装包、且 IT 愿意配合的场景。

### F. 不建议的做法

| 做法 | 为什么不建议 |
| --- | --- |
| 退出 / 关闭天擎 HIPS 模块 | 需要控制台密码；属**篡改安全客户端**（客户端带自我保护 `QesSelfProtectRules.exe`），大概率被拦并**上报**，是安全事件 |
| 改本地白名单文件（`soft_control_*.dat` 等） | 文件是**加密存储**的，且会被控制台策略覆盖；同属篡改 |
| 依赖"首次运行侥幸放行" | 不可复现，第二次起必拦（§4.4） |
| 绕开 Explorer 启动（改用脚本 / 计划任务 / 服务等） | 判定对象是**文件本身**而非父进程，不保证有效；且属于规避安全管控 |
| 自签名证书 + 往受信任根塞证书 | 只影响本机 Authenticode 校验，对天擎策略无效；且"把私钥在个人手里的证书塞进受信任根"本身就是安全团队会拦的高风险动作（详见 `09-更新说明.md` §4.1） |

## 7. 未验证 / 不确定的（不要当成结论）

1. **客户端信任区按钮是否可用**：本机取证时无法在不干扰用户桌面的前提下打开 GUI 验证，需人工点一次（§5-A）。
2. **"按签名者名称加白"在本公司控制台是否开放**：功能是官方文档明确有的，但是否被当前策略启用未知。
3. **判定是纯云端还是"本地库 + 云端"**：本机同时存在 `sfmg\data\identify_soft_cloud_v1.dat`（20 MB 云识别库）、`softmain.json`（28 MB 软件主库，**按 package_md5 索引**）与 `DB\identify_soft_local.db`，无法在客户端侧确定三条数据的优先级。
4. **提权是否影响判定**：没有反例也没有正例，故不作为结论（§4.3）。**不要依赖它。**
5. §3 表格中的时间均为本机时区（GMT+8）、日期为 2026 年。

## 8. 复核方法（自己再验一遍）

```powershell
# ① 当前是否有拦截记录（有 → 命中本文场景）
Get-ChildItem "$env:ProgramData\QI-ANXIN Tianqing\Log\module.HipsEngShim" -Filter *.log |
  Select-String -Pattern 'CloudRule|Strangesoftware' |
  Select-Object -Last 5 -ExpandProperty Line

# ② 判定种类分布（是否不止一种策略）
Get-ChildItem "$env:ProgramData\QI-ANXIN Tianqing\Log" -Recurse -Filter *.log |
  Select-String -Pattern 'szVirusName:\s*(\S+)' |
  ForEach-Object { $_.Matches[0].Groups[1].Value } | Group-Object | Sort-Object Count -Descending

# ③ 某个被拦文件的完整判定过程（含 md5 / productName / 结论）
Get-ChildItem "$env:ProgramData\QI-ANXIN Tianqing\Log\QCMProcMgr" -Filter *.log |
  Select-String -Pattern 'bcrm-desktop\.exe' -Context 0,12

# ④ 本机实际是否装了这类产品
Get-ItemProperty 'HKLM:\SOFTWARE\WOW6432Node\Microsoft\Windows\CurrentVersion\Uninstall\*' |
  Where-Object { $_.DisplayName -match '天擎|奇安信|EDR|Sentry' } |
  Select-Object DisplayName, DisplayVersion, InstallLocation
```

**最快判据**：双击后 **目标目录里没有程序自己的日志** + **天擎拦截日志里有对应时间的记录** ⇒ 100% 是"进程创建被拦"，与程序代码无关。
