# 12 · 启动与环境说明（Web 版源码包）

> 本文对应交付包 `bcrm-web-3.1.zip`，讲清「拿到源码后怎么把它跑起来」。
> 面向第一次接触本项目、需要把 Web 版部署起来的人。

---

## 一、这个包是什么

BCRM 客户管理系统 · **Web 版**，**源码包**。

跑起来之后的形态：**一个进程、一个端口**，浏览器访问。目标机不需要 WebView2，也不需要任何额外运行时。

包里**没有** `target\`、`node_modules\`、`dist\` —— 这三个目录都要你自己生成（见第三节）。这是「最小」的含义：只带人写的文件。

---

## 二、环境要求

| 组件 | 版本 | 必需 | 说明 |
| --- | --- | --- | --- |
| Rust | 1.75+（stable） | ✅ | 编译后端 |
| Node.js | **18 或更高** | ✅ | 构建前端（Vite 5 要求 18+） |
| Visual Studio 生成工具 | 2019/2022，勾选「使用 C++ 的桌面开发」 | 视情况 | Rust 在 Windows 上默认用 MSVC 链接器；已装过完整 VS 就无需单独装 |
| 浏览器 | Edge / Chrome 等现代浏览器 | ✅ | 用户侧入口 |

自查：

```bat
rustc --version
cargo --version
node -v
npm -v
```

装了 Rust 之后**要重开一个命令行窗口**，PATH 才会生效。

> **只想运行、不打算改代码**的话：只做第三节的第 1、2 步，然后把 `backend\target\release\bcrm-backend.exe` 和 `frontend\dist\` 拷到一台**不装 Rust/Node** 的机器，用 `--web-dir` 指向 `dist` 就能跑。

## 三、从源码到跑起来

### 1. 构建前端

```bat
cd frontend
npm install
npm run build
```

产物在 `frontend\dist\`（`index.html` + `assets\`）。网络慢就换镜像：

```bat
npm install --registry https://registry.npmmirror.com
```

### 2. 编译后端

```bat
cargo build --release --manifest-path backend\Cargo.toml
```

产物 `backend\target\release\bcrm-backend.exe`（约 3.5 MB）。
首次 5–8 分钟（拉依赖 + LTO），之后是增量，很快。

> 这两步**没有先后依赖**：Web 版的前端产物是运行时通过 `--web-dir` 挂上去的，不像桌面版那样要内嵌进 exe。

### 3. 一键启动

**双击根目录的 `启动Web版.bat`。** 它会：

1. 检查是否已有实例在跑（有就直接开浏览器，不重复起进程）
2. 找到 `bcrm-backend.exe` 与 `frontend\dist\index.html`
3. 从 8787 起找一个空闲端口（被占自动顺延，最多试 20 个）
4. 起服务 —— 接口与页面在同一个进程里
5. 等就绪，自动打开浏览器

**关闭那个窗口 = 停止服务。**

### 4. 手工启动（等价做法）

```bat
backend\target\release\bcrm-backend.exe ^
    --web-dir frontend\dist ^
    --db data\crm.db ^
    --port 8787
```

浏览器打开 `http://127.0.0.1:8787/`。

### 5. 另一种启动方式（可选）

根目录还带了一组 `启动Web服务.bat` / `启动Web服务.ps1`，它更「自动」：会替你跑 `cargo build`、`npm install`，并区分 dev（热更新）/ release 两种模式。适合改代码时用。

```bat
启动Web服务.bat                  开发模式：后端 + 前端热更新
启动Web服务.bat -Mode release    交付形态：后端 + 前端构建产物
启动Web服务.bat -Stop            停止服务
```

## 四、启动参数

| 参数 | 默认 | 说明 |
| --- | --- | --- |
| `--port <端口>` | 8787 | 监听端口 |
| `--host <地址>` | `127.0.0.1` | 监听地址。⚠️ 改 `0.0.0.0` 前先读第六节 |
| `--db <文件>` | 自动定位 | 数据库文件 |
| `--web-dir <目录>` | 自动探测 | 前端产物目录（须含 `index.html`） |
| `--no-web` | — | 强制纯 API 模式，不做静态托管 |
| `--db-check` | — | 只做数据库自检并打印报告后退出 |
| `-h` / `--help` | — | 查看帮助 |

`启动Web版.bat` 也接受参数：

```bat
启动Web版.bat                   默认 127.0.0.1:8787
启动Web版.bat 9000              改用 9000 端口
启动Web版.bat 9000 0.0.0.0      监听所有网卡（⚠️ 先读第六节）
```

**不给 `--web-dir` 时会自动探测**，按顺序找：exe 同级 `web\`、`dist\` → 源码树 `frontend\dist\` → 当前目录下的 `web\`、`frontend\dist\`。全都找不到就退化成纯 API 服务，**不报错**。

## 六、⚠️ 安全边界（重要）

**当前后端 API 没有任何鉴权。** 任何能访问到这个端口的人，都能读写全部 62 张表。

- 默认只绑 `127.0.0.1`，只有本机能访问 —— 单机使用可以接受
- 要用 `--host 0.0.0.0` 开放给局域网之前，必须确认其一：
  - 这台机器不在能上外网的网络里，**或者**
  - 已在前置反向代理上加了访问控制（Basic Auth / IP 白名单 / 公司 SSO）

> 不要把 `0.0.0.0` 直接暴露到公网。

## 七、数据库

- **位置**：默认在 exe **同级目录**（便携模式）；该目录不可写时回退 `%LOCALAPPDATA%\Bcrm\crm.db`
- **首次运行自动建库**：62 张表 + 32 个索引 + 1 行初始数据
- **备份就是拷 `crm.db` 这一个文件**（服务停止时拷最稳妥）
- ⚠️ 在源码树里直接跑时，默认落点是 `backend\target\release\crm.db` —— 它在 `target\` 里，**`cargo clean` 会把库一起删掉**。所以 `启动Web版.bat` 显式把库指到 `data\crm.db`，手工启动时请照做。

表结构分组与关键业务口径，见 `文档\06-数据库架构解析.md`；完整建库 DDL 见 `文档\08-客户管理系统SQLite建库语句.md`。

## 八、常见问题

### 双击 bat 没反应 / 浏览器没打开

先看**窗口里的文字**，再看 `data\web-server.log`。脚本失败时会把服务端的真实输出直接打到窗口里，通常一眼就能看出原因。

### 窗口里说「日志都没生成」

说明进程**压根没被创建** —— 本机有终端管控软件（奇安信天擎等）在**进程创建阶段**拦住了 `bcrm-backend.exe`。

- 把 `bcrm-web-3.1\` **整个目录**加进信任区（按目录加，不要按文件，否则每重编一版都要重加）
- 右键「以管理员身份运行」**不能**绕过；给 exe 签名也**不能**
- 原理与加白申请单见 `文档\10-终端管控拦截：机制与解决方案.md`

### 端口被占用

脚本会自动往后找空闲端口（最多 20 个），窗口里会显示实际地址。也可以用 `启动Web版.bat 9000` 自己指定。

### `npm install` 很慢或失败

换镜像：`npm install --registry https://registry.npmmirror.com`

### 页面打开了但没有数据

新库本来就是空的。去「数据管理」新建记录，或导入数据。

### 改了建库语句（DDL）却不生效

`schema.sql` / `schema.json` 是**编译期内嵌**进 exe 的 ⇒ 改完必须**重新 `cargo build --release`**，只重启服务没用。

### 想同时改前端看效果

用 `启动Web服务.bat`（dev 模式，热更新），不要用构建产物。
