BCRM 客户管理系统 · 桌面版使用说明
================================================================
版本 1.0.0    适用系统 Windows 10 / 11（64 位）
================================================================
交付目录里一共有 4 个文件：
    bcrm-desktop.exe                        便携单文件版（绿色版）
    BCRM客户管理系统_1.0.0_x64-setup.exe     安装包
    修复启动.bat                            一键排查 / 修复工具
    使用说明.txt                            本文件


【一、两种程序，按场景选一个】

1) BCRM客户管理系统_1.0.0_x64-setup.exe   —— 安装包（推荐给最终用户）
   · 双击 → 一路「下一步」即可，约 5 MB。
   · 安装模式是「仅当前用户」，装到 %LOCALAPPDATA% 下：
     不需要管理员权限，也不会因为目录只读而打不开。
   · 安装过程中会自动检测 Microsoft Edge WebView2 运行时；缺失时
     自动联网安装（程序里内嵌的是微软官方「在线引导器」，约 2 MB）。
     所以：第一次安装在**联网环境**下最省事。
   · 数据库文件放在程序目录里，卸载程序**不会**删除它（不会丢数据）。

2) bcrm-desktop.exe                        —— 便携单文件版
   · 不安装、不写注册表，整个文件夹拷到哪都能跑（U 盘、别的电脑都行）。
   · 数据库就是 exe 同级的 crm.db，跟着文件夹一起走。
   · ⚠️ 便携版不会自动装 WebView2。全新系统 / 精简系统第一次双击时，
     程序会检测到缺失、弹窗并给出官方在线安装链接（约 2 MB，需联网），
     装完再双击即可。具体见下面【三】的原因 A。


【二、日常使用】

· 双击 exe（或开始菜单里的快捷方式）即可。后端服务随界面一起启动，
  关窗即退出，不常驻后台、不占固定端口。
· 数据保存在 crm.db（SQLite）里。
  备份 = 关闭程序后复制 crm.db 这一个文件即可。
  注意：程序运行中会多出 crm.db-wal / crm.db-shm 两个临时文件，
        备份请在**程序关闭后**做，避免拷到一半的数据。
· 首次运行是**空库**：程序会自动建好 62 张业务表，并写入 1 行组织根节点
  （「奇安信集团」）。业务数据需要你在界面里录入，或用「数据管理」导入。
  所以第一次打开时列表是空的 —— 这是正常的，不是数据丢了。
· 数据库位置不是写死的，程序会按顺序找一个「能写」的位置：

     ① exe 同级的 crm.db            —— 便携模式，首选
     ② %LOCALAPPDATA%\Bcrm\crm.db   —— ①不可写时自动回退
     ③ 当前工作目录的 crm.db        —— 前两个都取不到时的最后兜底

  实际用了哪个，看程序目录下的 bcrm-launcher.log，里面有一行：
        数据库: <路径>（便携模式 / 用户目录）

· 两种情况会自动「搬家」，不会让你看到空库、也不会丢数据：
     a) ①里已经有数据、但 exe 目录不可写
        （典型：管理员把程序装到 Program Files，普通用户双击）
        → 程序把①的库**连同 crm.db-wal 一起复制**到②再用。
     b) ①里的 crm.db 被设成了只读
        （典型：从光盘 / 只读共享 / 只读U盘拷过来）
        → 同样复制到②，并**去掉只读属性**后再用。
  这两种情况下日志里会写明「已从 … 拷贝初始数据库」。


【三、双击没反应？按这个顺序排查】

第 0 步（最重要，先看这一个）：是不是被杀毒 / 终端安全软件拦了？
     判别方法：**程序目录里连日志文件都没生成**。
               程序启动的第一件事就是写 bcrm-launcher.log。连它都没有，
               说明进程根本没被创建 —— 那问题就不在程序本身，是被拦了。
     症状：双击后完全没反应，不出窗口，目录里也找不到 bcrm-launcher.log。
     原因：企业统一装的终端安全软件（奇安信天擎、深信服 EDR、360 天擎等）
           会用云端策略把「未签名程序」判定为「陌生软件」，在进程被创建
           **之前**就拦掉。本程序没有代码签名证书，所以在**受管控的公司
           电脑上**很容易触发。
     已实测：奇安信天擎拦截本程序用的策略名是
               CloudRule.Block.Strangesoftware（「拦截陌生软件」）
     怎么确认：用管理员身份打开这个目录，看里面最新的 .log，
               搜索 bcrm-desktop.exe：
                 C:\Program Files (x86)\Qianxin\Tianqing\ifl\fcEng\defender\xdlog\
               能看到形如
                 CloudRule.Block.Strangesoftware(... \Application\bcrm-desktop.exe")
               的记录，就确认是被拦了。
               （别的品牌同理：在它的拦截日志 / 事件里搜 bcrm-desktop.exe。）

     三种解决办法，按推荐顺序：

       ①【推荐】把程序加入信任 / 白名单
          · 奇安信天擎：点右下角托盘图标打开客户端 → 找「病毒防护」或
            「程序管控 / 应用管控」→「信任区 / 白名单」，把这两个文件
            加进去（选「文件」类型，填完整路径）：
                bcrm-desktop.exe
                BCRM客户管理系统_1.0.0_x64-setup.exe
          · 如果之前弹过「拦截陌生软件」的窗口，窗口上一般有
            「信任 / 允许」按钮，直接点它也能放行。
          · 公司统一管控的电脑上，客户端的白名单可能是灰的、改不了。
            这种情况需要让 IT 在**天擎管理控制台**下发一条「信任区」策略，
            把上面两个文件名和 MD5 给 IT 即可。

       ②【临时可用】右键 →「以管理员身份运行」
          · 实测被拦截时，提权启动能绕过这条策略。
          · 缺点：每次都要多点一步。而且提权跑过之后，WebView2 缓存目录
            会变成管理员所有；本程序已内置**自愈**（普通用户下次双击时
            会自动删掉重建），因此不会因为这点而打不开。
          · 这只是应急手段，长期仍建议走 ①。

       ③【根本解决】给程序做数字签名
          · 用企业代码签名证书签名后，就不会再被判为「陌生软件」。
            这是对外分发程序的正解，需要走证书申请流程。

     注意：这种情况**程序自身无法规避** —— 拦截发生在进程创建之前，
           程序内部的任何兜底代码都来不及执行。

第 1 步：运行本目录的「修复启动.bat」
         它会依次做四件事：
           [1/4] 检查 WebView2 运行时，缺了就打开官方在线安装页
           [2/4] 检查 WebView2 用户数据目录的所有者与可写性，
                 可疑时询问是否删除（详见下面原因 B）
           [3/4] 跑一次数据库自检（弹出报告）
           [4/4] 启动程序
         全程有中文提示，照着做即可。

第 2 步：手工看日志（都在 exe 同一个目录里）
         · bcrm-launcher.log        启动过程，最后一行就是卡在哪一步
         · bcrm-launcher-error.log  本次致命错误的完整说明
         · bcrm-db-check.txt        数据库权限自检报告
         命令行执行 bcrm-desktop.exe --db-check 会重新生成这份报告。

         ⚠️ 如果上面三个文件**一个都没有** —— 回到第 0 步，
            是被终端安全软件拦了，不是程序的问题。

第 3 步：常见的几种原因

  A. 缺少 WebView2 运行时（界面根本出不来）
     现象：双击后没有任何窗口；但**日志文件是存在的**，而且里面
           **没有**「WebView2 运行时: v…」这一行。
     解决（联网）：直接双击程序，它会弹窗并提供「打开官方在线安装页」，
                   点「是」即可；装完重新双击。
                   手工下载地址：https://go.microsoft.com/fwlink/p/?LinkId=2124703
     解决（离线内网）：到能上网的机器打开
                   https://developer.microsoft.com/microsoft-edge/webview2/
                   下载「Evergreen 独立安装程序」里对应架构的包，拷过来装。
     说明：程序在**建窗口之前**就会检测运行时，缺了会明确弹窗，
           不会再出现"一闪而过什么都没留下"的情况。

  B. WebView2 用户数据目录被「管理员身份」创建过
     现象：双击没窗口，但日志里「WebView2 运行时: v…」这一行是正常的。
     位置（按优先级，程序二选一，日志里会写明实际用了哪个）：
           · exe 同级的 .bcrm-webview\
           · %LOCALAPPDATA%\Bcrm\WebView2\
     原因：这个目录一旦被提权进程创建过（右键「以管理员身份运行」，
           或安装向导结尾勾选「运行」那一次），普通用户双击时
           WebView2 无法接管它，界面自然出不来。而且**会一直复现**。
     解决：程序**已经自动处理**了 —— 启动时会体检该目录的所有者，
           发现「属于 Administrators/System 而当前是普通用户」就自动
           删除并重建（它只是浏览器缓存，**不影响** crm.db 业务数据）。
           日志里会写「已自动修复（原属 BUILTIN\Administrators…）」。
           若删除失败（权限不足），日志里会提示你手动删除该目录。
     预防：一律直接双击，不要用「以管理员身份运行」。
     提示：万一窗口仍然建不出来，程序会弹出完整诊断（所有者、可写性、
           修法），点「是」即删除并自动重启。

  C. 数据库目录不可写
     现象：日志里出现「初始化数据库失败」。
     解决：正常情况下程序会自动回退到 %LOCALAPPDATA%\Bcrm\（见【二】），
           不必手工干预。若仍失败，运行「修复启动.bat」看自检报告里
           每个候选位置被跳过的原因。
     注意：Windows 的「受控文件夹访问」（勒索软件防护）会拦截对
           桌面 / 文档目录的写入。如果开了这项防护，请把本程序加入
           允许列表，或改用安装包版本（装到 %LOCALAPPDATA%）。
     说明：自检报告会逐个列出候选位置的「目录是否可写 / 库文件是否可写 /
           写探针是否通过」，把这份 bcrm-db-check.txt 发给技术同事即可定位。


【四、卸载】

· 安装包版本：「设置 → 应用 → BCRM客户管理系统 → 卸载」。
· 便携版：直接删掉整个文件夹即可（不写注册表、不留残留）。
· 重要：卸载**不会**删除你的数据。crm.db 在程序目录里，
  彻底清理时请先备份，再手工删除：
    · 程序目录下的 crm.db（以及 crm.db-wal / crm.db-shm）
    · 程序目录下的 .bcrm-webview\ （WebView2 浏览器缓存，可放心删）
    · %LOCALAPPDATA%\Bcrm\ 目录（数据库回退到过那里时才有）


【五、高级：命令行自检（可脚本化）】

  bcrm-desktop.exe --db-check
      跑一次数据库权限自检，把报告写到 exe 同级的 bcrm-db-check.txt，
      并弹窗显示结果。等价于「修复启动.bat」的第 3 步。

  bcrm-desktop.exe --db-check --quiet
      同上，但不弹窗（也可设环境变量 BCRM_NO_DIALOG=1）。
      适合批处理 / 远程排障：看退出码（0=可用，1=不可用）+ 报告文件。

  报告内容包含：当前用户与权限、exe 路径、每个候选数据库位置的
  「是否存在 / 目录是否可写 / 库文件是否可写」、最终选用的位置、
  表数量、数据行数、写探针结果。


【六、技术信息（排查时可提供给开发）】

· 界面：Vue 3 + Vite，全部前端资源编译进 exe，无外部依赖。
· 外壳：Tauri 2（Windows 上用系统自带的 Edge WebView2 渲染）。
· 后端：Rust + axum，与界面同一个进程，只监听 127.0.0.1 的随机空闲端口
        （不占固定端口、不对外网开放）。
· 数据库：SQLite（WAL 模式），62 张业务表，首次运行自动建库。
· 跨源策略：后端 CORS 只放行 tauri://localhost 与 127.0.0.1 / localhost，
            本机其它网页无法读写你的客户数据。
